# 실제 입력에서 결과까지 구현하기

현재 과제와 프로젝트 지침을 우선하며 허용된 AI 작업 단계에서만 수행한다. 제출물 확정 이후에는 중단한다. 제공 환경·기존 권한 안에서 작업하며 외부 AI·개인 키·외부 전송·Git Push·화면 자동 조작을 사용하지 않는다.

## 이어받기

STATE와 관련 MISSION·PLAN·DATA, 실제 변경 상태를 확인한다. 이미 동작하는 부분을 지우거나 처음부터 다시 만들지 않는다. 필요한 계약이 없다면 가장 작은 작업에 필요한 수준만 정리하고, 업무 의미를 바꾸는 모호함은 질문한다.

중요한 미확정 규칙에 대한 추천안은 구현 승인이나 확정 계약이 아니다. 해당 동작은 답변 대기로 두고 독립 부분을 구현한다. 별도로 허용된 가정 실험은 확정 결과물과 분리하고 실험/미확정으로 표시한다. 기술 테스트 통과를 그 업무 규칙의 확정 근거로 사용하지 않는다.

## 구현 루프

1. 필수 요구 하나 또는 연결된 작은 흐름을 고르고, 대표 입력·기대 결과·수정 파일을 확인한다.
2. 실제 입력 → 처리 → 출력의 동작 경로를 만든다. 고정된 예시 결과나 모의 응답으로 실제 기능이 구현된 것처럼 보이게 하지 않는다.
3. 기존 구조·테스트·의존성을 우선 사용한다. 새 의존성이 필요하면 효과와 설치·통합 위험, 환경 허용 여부를 확인한다. 전역 설치·Codex 변경을 기본 해결책으로 삼지 않는다.
4. 중요한 정상·예외 경로를 실행하고 결과를 기록한다. 순수 계산은 독립 기대값으로 확인한다. 검증 결과 없이 완료했다고 말하지 않는다.
5. 같은 기준 안의 오류를 좁혀 수정한 뒤 원래 실패 사례와 영향받는 검사를 다시 실행한다. 관련 없는 리팩터링이나 선택 기능으로 범위를 늘리지 않는다.
6. 확인된 단위를 통합하고 다음 필수 단위로 이어간다. 기능 설명은 변경 시 짧게 제공한다.

테스트·설명은 마지막까지 미루지 않는다. 실패가 반복되면 원인 가설·새 근거·대체 경로를 비교한다. 새 근거 없이 같은 설치·수정을 반복하지 말고 막힌 범위와 사용자에게 필요한 결정을 알린다.

## 병렬 구현과 통합

[공통 지침](../../AGENTS.md)의 조건부 기본 위임을 따른다. 실제 지원·공식 허용·독립 작업 조건이 맞으면 작업자 1명부터 구현을 맡기고 메인은 대화·핵심 판단·통합을 담당한다. 작은 수정이나 서로 강하게 의존하는 작업은 직접 처리한다. 작업별 파일 소유와 입출력 계약을 지키며 공통 파일·스키마·의존성·상태 문서는 메인이 갱신한다.

작업자는 변경 파일, 실제 확인 명령·결과, 미완료·위험을 반환한다. 다른 작업자의 변경을 덮어쓰지 않는다. 검증 중인 코드가 바뀌면 검증 대상 기준점을 명시하고 통합 후 영향받는 검사를 다시 수행한다. 각각 통과한 결과를 전체 통합 통과로 대체하지 않는다.

전용 작업 폴더에 기록 작성이 허용된 작업자는 로컬 STATE·PLAN·EVIDENCE를 만들 수 있다. 부모 공유 기록은 수정하지 않고 로컬 기록 위치와 결과를 메인에 반환한다.

## 산출물과 상태

- 실제 코드·설정·필요한 결과물이 주 산출물이다. PLAN의 작업 상태·구현 위치를 갱신한다.
- 실행 근거는 EVIDENCE, 중요한 선택은 DECISIONS, 다음 행동·막힘은 STATE에 연결한다.
- 사용자에게 `완성한 동작 / 실제 검증 / 남은 위험·다음 작업`을 짧게 설명한다.

미검증 구현과 검증된 동작을 구별한다. 시간 부족 시 선택 기능을 줄이되 필수 누락은 드러낸다. 커밋·새 브랜치·배포·제출은 이 스킬의 자동 동작이 아니며 별도 요청과 실제 규칙을 따른다.
