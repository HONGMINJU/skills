# 실제 입력에서 결과까지 구현하기

현재 과제와 프로젝트 지침을 우선하며 허용된 AI 작업 단계에서만 수행한다. 제출물 확정 이후에는 중단한다. 제공 환경·기존 권한 안에서 작업하며 외부 AI·개인 키·외부 전송·Git Push·화면 자동 조작을 사용하지 않는다.

시작할 때 아직 읽지 않은 [공통 지침](../../AGENTS.md)을 먼저 확인한다. 이번 세션에서 읽은 같은 버전이면 반복하지 않는다. 파일이 없으면 공통 규칙 미확인임을 알리고 현재 프로젝트 지침과 요청 범위 안에서 진행한다.

## 이어받기

STATE와 관련 MISSION·PLAN·DATA, 실제 변경 상태를 확인한다. QNA의 관련 질문·최신 적용 답변·미반영 항목을 함께 읽고 해당 작업의 기준을 맞춘다. 이미 동작하는 부분을 지우거나 처음부터 다시 만들지 않는다. 필요한 계약이 없다면 가장 작은 작업에 필요한 수준만 정리하고, 업무 의미를 바꾸는 모호함은 질문한다.

중요한 미확정 규칙에 대한 추천안은 구현 승인이나 확정 계약이 아니다. 해당 동작은 답변 대기로 두고 독립 부분을 구현한다. 별도로 허용된 가정 실험은 확정 결과물과 분리하고 실험/미확정으로 표시한다. 기술 테스트 통과를 그 업무 규칙의 확정 근거로 사용하지 않는다.

핵심 알고리즘은 DECISIONS의 사용자 선택·확인 상태를 이어받는다. 미선택이거나 중대한 변경이 필요하면 [fde-design](../fde-design/SKILL.md)의 비교·대화로 연결하고, 합의된 구현과 독립 작업은 계속한다.

## 구현 루프

웹 과제라면 기존 앱이나 최소 실행 골격이 준비되는 대로 복잡한 계산 구현에 앞서 실행법·실제 포트·미리보기 경로, 서버 기동과 최소 요청을 확인한다. 제공 브라우저의 첫 접속이 아직 미확인이면 참가자에게 최소 확인을 요청한다. 완성 UI를 선행 조건으로 삼거나 접속 답변을 기다리며 독립 작업까지 멈추지 않는다. 환경·접속 문제와 코드 오류를 구분하고 제한을 우회하지 않는다. 화면 없는 과제에는 적용하지 않는다.

1. 필수 요구 하나 또는 연결된 작은 흐름을 고르고, 대표 입력·기대 결과·수정 파일을 확인한다.
2. 실제 입력 → 처리 → 출력의 동작 경로를 만든다. 고정된 예시 결과나 모의 응답으로 실제 기능이 구현된 것처럼 보이게 하지 않는다.
3. 기존 구조·테스트·의존성을 우선 사용한다. 새 의존성이 필요하면 효과와 설치·통합 위험, 환경 허용 여부를 확인한다. 전역 설치·Codex 변경을 기본 해결책으로 삼지 않는다.
4. 중요한 정상·예외 경로를 실행하고 결과를 기록한다. 순수 계산은 독립 기대값으로 확인한다. 검증 결과 없이 완료했다고 말하지 않는다.
5. 같은 기준 안의 오류를 좁혀 수정한 뒤 원래 실패 사례와 영향받는 검사를 다시 실행한다. 관련 없는 리팩터링이나 선택 기능으로 범위를 늘리지 않는다.
6. 확인된 단위를 통합하고 다음 필수 단위로 이어간다.

작업 단위 시작·전환점에는 PLAN의 개선 중단 시각과 남은 필수 작업을 확인하고 [공통 지침](../../AGENTS.md)의 마감 전 집중 전환을 적용한다. 테스트·설명은 마지막까지 미루지 않는다. 실패가 반복되면 원인 가설·새 근거·대체 경로를 비교한다. 새 근거 없이 같은 설치·수정을 반복하지 말고 막힌 범위와 사용자에게 필요한 결정을 알린다.

구현 중 새 예외·운영 충돌은 해당 입력·영향·기존 Q ID와 함께 [공통 QNA 절차](../../AGENTS.md#q--a--반영여부-사용법)로 연결한다. 미확정 업무 판단을 코드로 먼저 고정하지 않고 실제 답변을 관련 요구·계약·코드·테스트에 반영한다. 스키마·스택 등 이미 합의한 구현 선택은 이유 없이 담당자에게 다시 묻지 않는다.

## 계산 결과를 서비스에 연결할 때

계산·탐색·최적화 결과를 사용하는 기능에만 적용한다. 실제 입력·설정으로 제품의 계산 경로를 호출하고, 반환된 결정·목표값과 단위·계산 상태를 필요한 API·화면·저장·내보내기에 연결한다. 독립 검사 방식은 [fde-verify](../fde-verify/SKILL.md)를 따른다.

- 유효하지만 최적성 미증명인 결과, 증명 범위 내 최적 결과, 모델상 불가능, 제한시간 내 해를 못 찾음, 입력·실행 오류를 실제 지원하는 범위에서 구별한다. 솔버 상태만으로 업무 모델의 정확성까지 보장하지 않으며, 화면의 성공 문구로 미충족 조건을 숨기지 않는다.
- 장시간 계산·탐색에는 시간·작업량 한도를 두고 제한 도달 시의 응답을 정한다. 이미 독립 검증한 후보를 반환할 수 있으면 사용한 입력과 미증명·미충족 조건을 함께 표시한다. 검증되지 않은 후보나 이전 요청의 결과를 성공으로 대신 반환하지 않는다.
- 입력·설정 변경 시 이전 결과를 오래됨으로 표시하거나 현재 결과에서 제외하고, 합의된 실행 방식으로 재계산한다. 비동기 요청이 있다면 이전 응답이 최신 결과를 덮지 않게 한다. 캐시가 실제로 필요할 때만 결과를 바꾸는 입력·설정·모델 버전을 키에 반영한다.

요구에 없는 비동기 처리·캐시·DB·별도 작업 큐를 이 지침 때문에 추가하지 않는다.

## 병렬 구현과 통합

위임 조건·파일 소유·보고 범위는 [공통 지침](../../AGENTS.md)을 따른다. 통합할 변경을 합의된 입출력 계약과 대조한다. 검증 중 코드가 바뀌면 대상 기준점을 구분하고 통합 후 영향받는 검사를 다시 수행한다. 개별 작업의 통과를 전체 통합 통과로 대체하지 않는다.

## 산출물과 상태

- 실제 코드·설정·필요한 결과물이 주 산출물이다. PLAN의 작업 상태·구현 위치를 갱신한다.
- 실행 근거는 EVIDENCE, 중요한 선택은 DECISIONS, 다음 행동·막힘은 STATE에 연결한다.
- [공통 지침의 짧은 원리 설명](../../AGENTS.md#개발-중-짧은-원리-설명)에 실제 동작·검증·남은 위험과 다음 작업을 연결한다. 설계 때 설명한 내용은 반복하지 않고 달라진 부분을 알린다.

미검증 구현과 검증된 동작을 구별한다. 시간 부족 시 선택 기능을 줄이되 필수 누락은 드러낸다. 커밋·새 브랜치·배포·제출은 이 스킬의 자동 동작이 아니며 별도 요청과 실제 규칙을 따른다.
