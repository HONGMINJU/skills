# 데이터 의미부터 확인하기

현재 과제와 제공 환경의 규칙을 따른다. AI 사용이 허용된 작업 단계에서만 수행하고 제출물 확정 이후에는 중단한다. 원본 데이터는 보존하며 외부 서비스·검색·모델로 전송하지 않는다.

시작할 때 아직 읽지 않은 [공통 지침](../../AGENTS.md)을 먼저 확인한다. 이번 세션에서 읽은 같은 버전이면 반복하지 않는다. 파일이 없으면 공통 규칙 미확인임을 알리고 현재 프로젝트 지침과 요청 범위 안에서 진행한다.

## 입력과 범위

MISSION의 관련 요구·QNA의 기존 담당자 답변과 실제 파일·스키마·작은 표본부터 읽는다. 데이터가 없거나 이미 확인한 내용을 다시 요구하지 않는 작업이면 필요한 확인만 하고 종료한다. 기존 DATA와 검사 스크립트가 있으면 변경된 입력·가정에 집중한다.

우선 행 하나의 관측 단위, 식별자·조인 관계, 숫자의 단위·분모, 기간·시간대, 기록 시점을 확인한다. 파일 이름만으로 의미를 확정하지 않는다. 재시도·반복 기록·중복 전송은 서로 다른 업무 의미일 수 있다.

독립적인 탐색·검산을 맡길 때는 [공통 지침](../../AGENTS.md)의 조건부 기본 위임을 따른다. 파일·열·검사 범위를 나누고 메인은 중요한 의미 확인과 대화를 맡는다. 작업자는 관찰·근거·질문을 반환하며 공유 DATA·MISSION·QNA의 최종 갱신은 메인이 담당한다. 작은 점검이나 지원되지 않는 환경에서는 직접 수행한다.

## 필요한 검사만 선택

- 읽기 조건: 인코딩·구분자·헤더·파싱 오류·큰 파일 처리. 기존 도구나 표준 라이브러리로 충분한지 먼저 확인한다.
- 품질: 결측의 의미, 형식이 섞인 열, 범위·불가능한 값, 완전 중복과 키 충돌, 잘린 행, ID의 선행 0·공백 등 실제 위험.
- 관계: 키의 유일성·조인 방향, 연결되지 않은 행, 조인 전후 행 수·합계 변화. 다대다 조인으로 수치가 부풀려지는지 확인한다.
- 계산: 합계·비율의 집계 단위와 분모, 제외 행, 단위 변환. 비율 평균과 전체 분자/분모 비율을 구별한다.

검사 범위와 표본 수를 명시한다. 표본에서 검사한 건수의 분모에 전체 행 수를 쓰지 않는다. 일부만 읽고 전체 유일성·결측률을 확인했다고 말하지 않는다. 오류를 조용히 대체해 읽었다면 무엇을 놓칠 수 있는지 밝힌다.

결측을 0으로 채우거나 중복·이상치를 제거하기 전에 업무 의미를 확인한다. 새 관찰이나 기존 답변과의 모순은 [공통 QNA 절차](../../AGENTS.md#q--a--반영여부-사용법)로 연결하고, 답변과 무관한 스키마·품질 검사는 계속한다. 실제 답변은 DATA의 의미·처리 계약과 기대값에 Q ID로 연결하고 기존 정제·집계·검증 결과의 영향을 확인한다. 데이터 탐색 단계라는 이유로 질문을 미루거나 답변을 DATA에만 따로 보관하지 않는다.

## 예측 과제일 때만

예측 시점에 사용할 수 있는 열과 정답 생성 시점을 구분한다. 배포 상황에 맞춰 시간·개체·그룹의 분할 조건을 검토하고, 학습/평가 사이 중복·누수를 확인한다. 데이터에 시간 열이 있다는 이유만으로 모든 문제에 같은 분할을 강제하지 않는다.

단순 기준선, 업무 제약에 맞는 지표, 검증 구간에서 결정할 임계값과 최종 평가 범위를 설계한다. 이 스킬의 기본 범위는 점검과 평가 설계이며 학습 실행은 별도 구현 범위에 따른다.

## 산출물

- DATA: 의미·단위·키·점검 범위·관찰 수치·처리 계약과 아직 모르는 점.
- 허용된 작업공간의 짧은 재실행 스크립트 또는 기존 검사 명령. 원본과 정제 결과를 분리한다.
- 독립 검산에 쓸 작은 입력과 기대값 근거. 실제 실행 결과는 EVIDENCE에 연결한다.
- 중요한 처리 결정은 DECISIONS, 질문은 QNA, 다음 행동은 STATE에 연결한다.

원본 전체를 Markdown에 복사하지 않는다. 근거가 없는 수치를 채우지 않으며, 품질 점검 통과를 과제 해결이나 모델 성능의 증명으로 해석하지 않는다.
