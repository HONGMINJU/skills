# 반도체 데이터 체크리스트

실제 반도체 검사·공정 데이터 점검에 필요한 항목만 선택한다. 실제 과제와 데이터 사전이 이 문서의 예시보다 우선하며, AI 사용이 허용된 제출물 확정 전 단계에서만 적용한다. 원본과 과제 자료를 외부로 전송하지 않는다.

## 1. 행과 식별자의 의미

| 확인할 것 | 결과를 바꾸는 구분 |
| --- | --- |
| 행 하나의 단위 | lot·wafer·die·package·검사 시도·결함 사건·센서 관측 중 무엇인지 |
| 개체와 검사 키 | 개체 ID와 검사 단계·시도·시간을 구분하고, 파일 전체에서 유일한 복합 키가 무엇인지 |
| ID 범위 | wafer 번호가 lot 안에서만 유일한지, 선행 0이나 문자열 표기가 의미를 갖는지 |
| 측정 조건 | 제품·장비·chamber·recipe·검사 단계·항목·단위·기간·시간대가 비교 가능한지 |

열 이름만으로 뜻을 확정하지 않는다. 같은 값의 반복이 정상 반복 측정인지, 재검인지, 중복 전송인지 확인한다. 필요한 구분 열이 없다면 그 한계와 결과에 미치는 영향을 남긴다.

## 2. 분자·분모와 집계 범위

- 통과 개체 수, 불량 개체 수, 결함 발생 건수, 검사 시도 수를 구분한다. 한 개체에 여러 결함이 생길 수 있으므로 `1 - 결함 건수 / 검사 개체 수`를 통과율로 사용하지 않는다.
- 동일 검사 정의와 서로 겹치지 않는 모집단의 집계라면 전체 통과율은 `통과 수 합계 / 검사 수 합계`로 검산한다. 그룹별 비율 평균과 다르며, 이미 겹친 집계 행을 다시 합산하지 않는다.
- 합성 검산 예: 10개 중 9개, 다른 90개 중 45개가 통과했다면 전체는 54/100 = 54%다. 90%와 50%의 단순 평균인 70%가 아니다. 이는 계산 예시이지 실제 과제의 기대값이 아니다.
- 선정한 검사 모집단의 통과율을 전체 제조·출하 수율로 확대하지 않는다. 대상 기간·검사 단계·포함/제외 조건을 결과와 함께 명시한다.
- 검사 수 0은 통과율 0%나 100%로 단정하지 않는다. 미관측·결측·실제 0을 구별하고, 음수·통과 수 초과·개수의 비정수 값은 계약에 따라 처리한다. 오류 행에서 전체 실패할지 제외 후 계속할지 임의로 정하지 않는다.
- 장비·제품별 결함 건수 순위를 비교할 때 검사량·가동량 같은 노출량 차이를 확인한다. 많은 건수만으로 높은 불량률이나 원인을 입증하지 않는다.

## 3. 재검·중복·조인

- 최초 검사 통과율, 최종 판정 통과율, 전체 검사 시도별 통과율은 별도 지표다. 개체 선정·검사 순서·승인된 최종 판정의 기준을 확인한다. 최신 시각을 무조건 최종 승인으로 보지 않는다.
- 재검 이력과 완전 중복 전송, 같은 키의 상충 값을 구별한다. 정책이 없으면 자동 중복 제거·마지막 행 선택·오류 제외로 숨기지 않는다.
- 조인의 좌우 키와 1:1·1:N·N:M 관계, 결측 키의 취급을 확인한다. 조인 전후 행 수뿐 아니라 고유 개체 수·검사 수·통과 수와 미연결 행도 비교한다.
- 결함 사건을 개체에 붙이면 한 개체가 여러 행이 될 수 있다. 조인된 행 수를 개체 수로 사용하거나 검사 합계를 반복 합산하지 않는다.

결과를 바꾸는 의미가 불명확하면 MISSION에 질문·영향·추천안·답변 의존 작업을 남긴다. 답변 전에는 관련 집계·판정을 확정하지 않고, 독립적인 스키마·파싱·키 충돌 조사는 계속한다.

## 4. 연속 계측·SPC가 실제로 필요한 경우

- 개별 연속 측정값인지 부분군 통계·비율·건수인지 먼저 구별한다. 도구가 있다는 이유로 통과율이나 결함 개수에 I-MR을 적용하지 않는다.
- 같은 장비·chamber·제품·recipe·항목·단위의 비교 가능한 흐름인지 확인한다. 실제 열 이름으로 식별 키를 정하고, 알려진 열 이름 몇 개를 자동 인식한 것만으로 단일 공정임을 보증하지 않는다.
- 시각 순서·중복 시각·시간대·관측 간격·누락 구간·정비나 조건 변경을 확인한다. 결측을 0으로 채우거나 구간을 무작정 이어 붙이지 않는다.
- 모니터링에 쓸 과거 기준 구간은 미래 관측을 보고 유리하게 바꾸지 않는다. 기준 구간의 안정성·측정 해상도·독립성/자기상관 등 적용 가정은 별도 검토 대상이다. 짧은 계산 예제나 특정 표본 수만으로 안정성을 선언하지 않는다.
- 과거 변동이 0이라고 완벽한 정상 상태로 판단하지 않는다. 적용 가능 여부를 확인하고 판정 불가를 구별한다.
- 관리한계와 제품 규격한계를 구분한다. 관리도 신호는 추가 조사 단서이지 불량 확정·원인 입증·장비 조정 명령이 아니다. 규격과 적용 가정 없이 공정능력 수치를 만들지 않는다.

이 문서는 적용 조건 점검이지 SPC 구현이나 공정 제어 절차가 아니다. 실제 과제가 요구할 때만 별도 설계·구현·검증으로 진행한다. 이 키트에는 `semi yield`·`semi spc` 실행 도구가 포함되지 않는다.

## 5. 예측이 요구되는 경우

기본 스킬의 예측 점검에 더해, 같은 개체의 재검 이력과 lot·wafer·시간 정보가 학습/평가에 걸쳐 섞이는지 확인한다. 예측 시점 이후 생긴 검사 결과·최종 판정·사후 집계는 당시 사용 가능한 입력으로 취급하지 않는다. 그룹 분리와 시간 분리가 동시에 필요한지 실제 배포 상황으로 판단하고, 대시보드·집계 과제에 모델 학습을 추가하지 않는다.

## 6. 남길 기록

- DATA: 확인한 관측 단위·키·검사 단계·분자/분모·재검/오류/조인 계약·실제 검사 범위와 근거. 미확인과 해당 없음을 구별한다.
- MISSION: 결과를 바꾸는 미확정 질문과 답변 의존 작업. 추천안을 승인된 업무 규칙으로 기록하지 않는다.
- DECISIONS: 확정된 처리 방식과 선택 이유·대안. 이전 기준이 바뀌면 영향도 연결한다.
- EVIDENCE: 독립 검산 입력·기대값 근거·실행 명령·실제 결과. 실행하지 않은 점검은 미실행으로 둔다.

체크리스트를 읽었다는 사실만으로 모든 항목을 검증 완료로 표시하지 않는다. 별도 도메인 보고서를 의무 생성하거나 원본 행 전체를 기록에 복사하지 않는다.
