# 문제 구조로 방법 후보 좁히기

알고리즘·최적화 방법 선택이 실제로 필요한 경우만 읽는다. 정답 알고리즘 목록이 아니라 후보를 찾는 출발점이다. 요구·규모·보장 수준과 기존 실행 환경을 먼저 확인하고 해당하는 행만 사용한다.

| 실제 결정의 구조 | 검토할 후보 | 채택 전에 확인할 것 |
| --- | --- | --- |
| 대상끼리 연결하면서 비용·정원을 맞춤 | 매칭·할당·최소비용 흐름 | 누가 반드시 배정돼야 하는지, 허용 조합과 추가 제약을 모델이 표현하는지 |
| 경로·네트워크를 따라 이동하거나 자원을 보냄 | 최단경로·흐름 알고리즘 | 간선 방향·비용·용량·도달 가능성, 별도 시간·방문 조건의 존재 |
| 한정 자원 아래 일부 항목을 선택 | 동적계획법·분기한정·정수계획 | 상태 수·계산량, 항목 간 상호작용과 선택 단위 |
| 시작 시간·선후관계·공유 자원을 함께 결정 | 제약 프로그래밍·정수계획 | 겹침·가용 시간·마감·작업 길이와 설치된 도구의 표현 가능 범위 |
| 연속 값을 나눠 배분하며 식이 선형 | 선형계획 | 목적·제약의 선형성, 변수 범위, 정수 결정이 섞였는지 |
| 선택 이력을 작은 상태로 요약해 반복 계산 | 동적계획법·제한된 탐색 | 상태가 미래에 필요한 정보를 빠뜨리지 않는지, 시간·메모리 증가량 |
| 작은 사례의 확실한 비교 답이 필요 | 손계산·완전탐색 | 관련 경우를 모두 포함할 수 있는 규모인지, 가지치기가 유효한지 |

- 여러 구조가 결합돼 있으면 각각 풀어 합친 결과가 전체 제약·목표를 만족하는지 별도로 판단한다. 표의 후보 이름만으로 적합성이나 최적성을 선언하지 않는다.
- 먼저 단순한 구조적 해법으로 요구를 표현할 수 있는지 확인한다. 탐색이 필요하면 입력 규모 대신 실제 상태·후보 수와 가지치기 조건으로 비용을 가늠하고 제한된 실험으로 확인한다. 모든 문제에 통하는 크기 임계값은 두지 않는다.
- 정확성 보장이 필요한데 시간·도구가 부족하면 그 요구를 미충족으로 남긴다. 휴리스틱·국소 개선은 유효한 후보를 찾는 선택지이지 전역 최적성의 증명이 아니다. 솔버의 종료 상태·허용 오차·유효한 경계가 있다면 해당 모델 범위에서 해석한다.
- 필수 조건을 임의의 벌점으로 바꾸거나 합의되지 않은 목표 가중치를 만들지 않는다. 단위 변환·정수화·반올림이 필요하면 원래 단위에서도 제약과 목표가 유지되는지 확인한다.
- 설치된 솔버를 사용할 때도 작은 모델의 실제 실행부터 확인한다. 새 패키지·외부 서비스 도입을 전제하지 않으며, 실행할 수 없다면 대안과 그 한계를 비교한다.

선택·대안·첫 검증·비교 중단 조건은 기존 DECISIONS에만 남긴다. 독립 검산과 유효성·품질·최적성 판정은 [fde-verify](../../fde-verify/SKILL.md), 실제 서비스 연결은 [fde-build의 계산 결과 계약](../../fde-build/SKILL.md#계산-결과를-서비스에-연결할-때)을 따른다. 이 자료를 읽는 것만으로 구현·실험 권한이 생기지 않는다.
