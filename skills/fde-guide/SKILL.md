# 처음 쓰는 사람의 길잡이

목표는 사용자가 스킬 이름을 외우지 않고 다음 행동을 선택하게 하는 것이다. 도움말 요청은 기본적으로 안내만 수행한다. 설치·설정 변경·개발·테스트·문서 초기화를 자동 시작하지 않는다.

## 현재 필요한 도움 고르기

- 전체 사용법을 묻는다면 하네스는 작업 운영 방식, 스킬은 작업 지침, 에이전트는 작업자라는 차이를 짧게 설명하고 입력할 문장 하나를 준다. 긴 용어 사전을 기본으로 출력하지 않는다.
- 다음 행동을 묻는다면 현재 작업공간의 실제 준비 기록 또는 STATE와 관련 근거를 필요한 만큼 읽는다. 빈 양식을 실제 과제 상태로 취급하지 않는다. 현재 위치만 묻는 경우 상태 조회에 집중한다.
- 작업공간의 스킬 목록·실제 SKILL.md·제공 환경의 발견 정보 중 확인 가능한 것을 사용한다. 파일 존재, 읽어서 적용, 자동 발견·등록은 서로 구분한다.
- 기능 이름은 이해하기 쉽게 말하고, 호출 이름은 실제 존재가 확인된 경우에만 제시한다. 핵심 작업 스킬이 아직 없으면 미구현임을 밝히고 일반 요청 문장과 기존 운영 문서로 안내한다. 임의의 명령·플러그인·스킬을 만들어내지 않는다.
- 경로를 제시할 때는 현재 작업공간에서 확인한 실제 경로를 사용한다. 개인 홈이나 전역 설정을 살피거나 바꿀 필요는 없다.

## 기능 선택 기준

다음 표는 이 키트의 기능과 스킬 파일 이름이다. 실제 파일 존재와 현재 환경의 등록 여부를 확인한 뒤 현재 결정에 필요한 한 가지를 먼저 추천한다. 일부 스킬만 가져온 환경이면 없는 파일을 호출하지 않는다.

| 현재 필요한 것 | 추천 기능 | 스킬 이름 | 남길 산출물 |
| --- | --- | --- | --- |
| 사용자·성공 기준·범위가 불명확함 | 문제정의·담당자 질문 | fde-discover | MISSION의 요구·질문·가정 |
| 행·키·단위·데이터 품질이 불명확함 | 데이터 이해·검증 | fde-data-audit | DATA의 의미·점검 근거 |
| 구현 순서·입출력·담당 범위를 정해야 함 | 설계·작업 분해 | fde-design | PLAN의 최소 흐름·계약·작업 |
| 요구와 기대 결과가 정해짐 | 작은 단위 개발·통합 | fde-build | 실제 코드와 PLAN |
| 동작 확인 또는 재현된 오류 해결이 필요함 | 검증·디버깅 | fde-verify | 테스트·로그와 EVIDENCE |
| 코드 동작과 실제 업무 해결을 대조해야 함 | 현업 시나리오 확인 | fde-acceptance | EVIDENCE의 실제 관찰·피드백 |
| 실행법·선택 이유·한계·제출 준비를 정리해야 함 | 설명·인계 | fde-handoff | HANDOFF와 기존 근거 연결 |

기록이 오래됐거나 요구가 바뀌면 필요한 범위만 다시 확인한다. 매번 7단계를 처음부터 돌리거나 모든 스킬을 동시에 읽지 않는다. 사용법 설명만 요청했다면 실제 과제 내용까지 조사할 필요는 없다.

## 초보자용 응답

- **추천:** 필요한 기능 하나와 이유.
- **이렇게 요청:** 사용자가 그대로 입력할 수 있는 짧은 문장. 등록을 확인하지 못했다면 일반 문장 또는 확인한 SKILL.md 경로를 사용한다.
- **얻게 될 것:** 실제 코드·문서·검증 결과 중 어떤 산출물이 생기는지.
- **사용자가 할 일:** 실제로 필요한 판단·담당자 전달·수동 확인만 표시한다. 필요한 일이 없다면 억지로 질문하지 않는다.

중요한 선택이 열려 있다면 모호한 점, 선택의 영향, 추천안과 이유를 묻는다. 답변이 필요한 작업만 보류하고 독립 작업은 계속할 수 있게 안내한다. 이미 합의한 내용이나 확정된 AI 허용 단계를 반복 확인하지 않는다.

## 안내에서 실행으로 넘어갈 때

“방법 알려줘”와 “그 범위로 진행해줘”를 구별한다. 실행 요청이 있으면 기존 권한과 범위 안에서 관련 작업만 수행하고, 지원 여부를 확인하지 않은 멀티에이전트·모델 전환·새 도구 설치로 확장하지 않는다. 스킬이 없더라도 가능한 일반 작업을 막지 않는다.

이 도우미는 시험 규정을 변경하지 않는다. 공개 자료 이용을 이유로 외부 AI·개인 키·외부 전송·Git Push·Computer Use·Codex 업데이트를 제안하지 않는다. 실제 제공 환경의 제한은 우회하지 않는다. 제출물 확정 이후임이 알려지면 과제 내용 조회·다음 풀이 단계·구현 설명·후속 답변 코칭을 중단한다. 실제 평가 단계가 불명확할 때는 내용 처리 전에 단계만 확인한다.
