# 이해할 수 있고 다시 실행할 수 있게 인계하기

현재 과제·제출 규칙을 우선한다. 제출물 확정 또는 후속 질문 준비·평가 단계임이 알려지면 과제 내용 조회·설명·수정·답안 코칭을 중단한다. 실제 평가 단계가 불명확하면 먼저 단계만 확인하며 사전 연습이나 AI 허용 단계가 이미 명확하면 반복 질문하지 않는다.

## 설명할 근거

MISSION의 실제 요구, PLAN의 구현 위치, 관련 코드·결과물, DECISIONS와 EVIDENCE를 대조한다. 요약 문서만으로 실제 구현·테스트 상태를 확정하지 않는다. 전체 소스나 로그를 다시 읽기보다 중요한 경로와 남은 위험에 집중한다.

사용자가 특정 기능 설명만 원하면 해당 범위만 설명하고 전체 제출 절차를 강제하지 않는다. 설명만 요청했는데 코드 수정·테스트·제출을 자동 수행하지 않는다.

## 설명 순서

1. 누구의 어떤 문제를 실제로 해결했고 어떤 요구가 남았는지.
2. 어떤 입력을 어디에 넣고 어떤 결과를 어떻게 사용하는지.
3. 실제 파일·함수와 연결한 입력 → 핵심 처리 → 출력의 흐름, 중요한 분기·계산·오류 처리.
4. 왜 이 방식을 택했고 어떤 대안을 포기했는지. 실제 결정 기록을 사용하며 사용자의 판단을 꾸며내지 않는다.
5. 무엇을 어떤 근거로 검증했고 무엇은 확인하지 못했는지.
6. 어떤 입력·조건에서 실패하거나 판단을 사람에게 넘겨야 하는지.

짧은 대표 입력을 따라 설명하면 도움이 되는 경우 실제 또는 명확히 표시한 합성 사례를 사용한다. 코드와 다른 이상적인 설계를 설명하거나 암기용 후속 답안·예상 채점표를 만들지 않는다. 설명 제공을 이해 완료로 간주하지 않는다.

## 선택 모드: 내가 직접 설명하기

“내가 설명해볼게”, “한 질문씩 이해도를 확인해줘”처럼 연습을 요청한 경우에만 사용한다. 일반적인 “구현을 설명해줘” 요청을 퀴즈로 바꾸지 않는다. 개발 중 핵심 결정 하나를 점검할 때도 사용할 수 있으며 전체 인계 완료를 기다릴 필요는 없다.

1. 관련 실제 코드·결정·증거에서 질문할 근거를 확인한다. 구현이 없으면 없는 기능에 대해 묻지 말고, 제공된 연습 사례 또는 확인할 자료가 필요함을 알린다.
2. 현재 구현의 입력→출력, 선택 이유·대안, 검증 근거·한계 중 중요한 주제 하나를 골라 **질문 하나만** 제시하고 답변을 기다린다. 답변 전에 모범 답안이나 답을 사실상 알려주는 해설을 붙이지 않는다.
3. 사용자의 답을 근거와 대조해 맞는 부분, 잘못되거나 빠진 부분, 확인이 필요한 부분을 짧게 구분한다. 코드가 하는 일과 테스트로 입증한 일을 분리하고, 미실행·오래된 증거를 통과로 설명하지 않는다.
4. 막히면 필요한 개념이나 해당 코드 흐름을 짧게 설명한 뒤 같은 핵심을 자기 말로 다시 설명하도록 요청한다. 사용자의 답을 완성 답안으로 대필·첨삭하거나 암기 대본으로 바꾸지 않는다.
5. 재설명에서 확인한 내용만 인정하고 다음 주제로 갈지 결정한다. 사용자가 중단하거나 요청한 시간·범위가 끝나면 종료하며, 한 답변으로 전체 이해 완료나 예상 점수를 선언하지 않는다.

시간이 짧으면 핵심 결정 또는 검증 근거 한 가지에 집중한다. 실제 평가 문항을 예측하거나 별도 문제은행을 만들지 않는다. 연습 도중에도 제출물 확정이 알려지면 즉시 중단하며, 확정 후 대기 시간을 AI 연습 시간으로 취급하지 않는다.

세션을 이어갈 기록이 필요하면 작업 사본의 HANDOFF에 주제·근거 위치·다시 확인할 개념·다음 질문의 초점만 짧게 남긴다. 답변 대기와 재설명 확인을 구별하고 대화 전문·완성 답안은 저장하지 않는다. 연습 결과는 코드 테스트 통과나 사람의 업무 수용 완료가 아니다.

## 실행·제출 준비가 요청된 경우

과제의 실제 필수 파일·형식·실행법을 확인한다. 관련 검증 근거가 없거나 오래됐으면 허용 범위에서 핵심 경로를 실행하거나 필요한 확인을 제안한다. 실행하지 않은 상태는 미검증으로 둔다.

확인한 작업 폴더·명령·의존성·입력 조건·출력 위치·복구 방법을 남긴다. 비밀정보·개인 파일·불필요한 임시 결과가 제출 대상에 섞이지 않도록 확인하되, 실제 민감값을 출력하지 않는다. 저장·수동 미리보기·필수 제출 조치를 구분한다.

참가자에게 최종 저장·미리보기·제출물 확정은 직접 하도록 안내한다. 로컬 검사 통과가 플랫폼 제출 완료는 아니다. 외부 배포·Git Push·자동 제출·요청하지 않은 커밋을 수행하지 않는다.

## 기록

HANDOFF 또는 지정 인계 문서에 실제 완료 범위, 실행법, 코드 흐름, 결정·증거 링크, 한계와 남은 필수 조치를 남긴다. 성능 수치를 별도 문서에서 다시 만들어내지 않는다.

새 검증은 EVIDENCE, 중요한 변경은 PLAN·DECISIONS, 제출 전 준비 상태는 STATE에 연결한다. 실제 확정 여부를 관찰하지 않았다면 확정 완료로 기록하지 않는다. 인계 후에도 미검증·미완료 항목을 숨기지 않는다.
