# 현재 위치 알려주기

기본은 읽기 전용이다. 상태 질문을 파일 갱신·계획 재작성·테스트·설치·작업 재개의 요청으로 확대하지 않는다. 현재 사용자에게 필요한 단계와 다음 행동을 한국어로 짧게 알려준다.

## 무엇의 상태인지 찾기

- 대화와 지정 작업공간에서 대회 준비인지 실제 과제 수행인지 구별한다. 준비 중이면 실제 준비 기록(예: PREPARATION.md), 과제 중이면 해당 과제의 STATE와 연결된 기록을 사용한다.
- 파일명만으로 상태의 정본을 결정하지 않는다. 실제 과제명·작업 위치·내용을 확인한다. `templates/`의 빈 양식이나 예시, 다른 과제 기록은 현재 상태의 증거가 아니다.
- 작업 사본에 양식 안내 문장이 남아 있어도 실제로 채운 내용과 근거를 보고 판단한다. 반대로 파일이 있다는 이유만으로 초기화·완료됐다고 보지 않는다.
- 현재 작업공간 안에서 필요한 파일만 찾는다. 정본 후보가 여럿이고 맥락으로 구별되지 않으면 어느 과제·폴더인지 한 번 묻는다. 자료가 없으면 미확인으로 답하고 자동 초기화하지 않는다.
- AI 허용 단계가 이미 확인됐다면 반복 질문하지 않는다. 제출물 확정 이후임이 알려졌다면 과제 내용 조회·평가·설명 없이 AI 지원 종료 경계만 안내한다. 실제 평가 단계가 불명확해 내용 접근 여부가 달라질 때만 단계부터 확인한다.

## 근거를 좁혀 읽기

STATE 또는 준비 기록을 먼저 읽고, 답에 필요한 PLAN·MISSION·QNA·EVIDENCE·실제 파일만 추가 확인한다. 긴 대화·로그·모든 스킬을 다시 읽지 않는다.

- 준비 단계와 과제의 문제정의·데이터 확인·설계·개발·테스트·현업 확인·인계를 혼동하지 않는다. 주된 단계와 병행 작업을 함께 표시할 수 있다.
- 완료 선언은 해당 범위의 산출물과 근거로 판단한다. 문서 작성, 코드 구현, 실행 검증, 사용자 확인은 별개다.
- 기록의 선언과 확인 가능한 실제 파일이 다르면 차이를 밝힌다. 증거 이후 관련 변경이 있으면 과거 통과와 현재 미검증을 구별한다. 파일 수정 시각만으로 검증의 유효·무효를 단정하지 않는다.
- 테스트를 새로 돌리지 않았다면 기록된 결과임을 드러낸다. 파일이나 근거에 접근할 수 없으면 그 범위를 미확인으로 남긴다.
- 완료율·남은 시간·모든 테스트 통과를 추정하지 않는다. 숫자를 요청받아도 분모·시각·판정 근거가 확인된 범위만 제시한다.

## 기본 응답

보통 다음 다섯 줄이면 충분하다. 사용자가 특정 항목만 물으면 필요한 부분만 답한다.

```text
현재: [준비 또는 과제 단계] — [현재 작업]
근거: [확인한 기록·파일·증거와 미확인 범위]
완료: [실제로 확인한 범위]
막힘/질문: [가장 중요한 위험 또는 필요한 결정]
다음: [행동 하나]
```

기록 정정이나 재검사가 필요하면 다음 행동으로 제안하되 조회만으로 수행하지 않는다. 이후 사용자가 진행을 요청하면 해당 범위와 기존 권한을 확인해 이어간다. 질문할 때는 영향과 추천안을 함께 제시하고, 안내 요청만으로 새로운 에이전트를 실행하지 않는다.
