# 문제를 실행 가능한 요구로 바꾸기

현재 과제 안내·프로젝트 지침·최신 운영 규칙을 우선한다. 실제 평가 중 AI 사용 단계가 불명확하면 내용 처리 전에 확인하고, 제출물 확정 이후라면 과제 지원을 중단한다. 이미 확인한 단계는 반복해서 묻지 않는다.

시작할 때 아직 읽지 않은 [공통 지침](../../AGENTS.md)을 먼저 확인한다. 이번 세션에서 읽은 같은 버전이면 반복하지 않는다. 파일이 없으면 공통 규칙 미확인임을 알리고 현재 프로젝트 지침과 요청 범위 안에서 진행한다.

## 읽을 것

실제 과제 README, 제출 조건, 제공 파일 목록과 작은 표본, 기존 MISSION·QNA·STATE 중 관련 부분을 읽는다. 준비용 예시나 빈 양식을 실제 문제로 대체하지 않는다. 이미 진행 중이면 기존 합의에서 변경된 부분만 확인한다.

## 정리할 것

- **업무:** 누가 언제 쓰며, 지금 어떻게 처리하고, 무엇이 어렵고, 결과로 어떤 판단·행동을 해야 하는가?
- **성공:** 필수 기능·제출 형식·성능 또는 운영 제약을 관찰 가능한 기준으로 바꾼다. 공개되지 않은 배점·숨은 요구를 만들어내지 않는다.
- **범위:** 필수 요구와 선택 제안을 구분한다. 웹앱·ML·LLM 사용 자체를 목표로 정하지 않는다.
- **입출력:** 실제 입력과 필요한 출력, 대표 정상 사례·중요한 실패 사례를 찾는다. 업무 기대값을 모르면 추측으로 확정하지 않는다.

관찰한 기존 방식이나 수치가 없으면 기준선은 미확인으로 남긴다. 목표 수치를 측정 결과처럼 적지 않는다.

## 질문하는 방법

답변에 따라 구현·검증·범위가 크게 달라지는 질문부터 추린다. 각 질문에 모호한 점, 선택 영향, 추천안과 이유, 답이 필요한 작업을 담는다. 이미 안내에 있는 내용을 다시 묻지 않는다.

사용자의 선호·수용 판단과 업무 담당자만 아는 데이터·현업 규칙을 구별한다. 담당자 질문은 참가자가 전달할 초안으로 작성하며 실제 전송·답변·승인을 가장하지 않는다. 답변이 없으면 영향받는 작업만 보류하고 파일 구조 확인 등 독립 작업은 계속한다.

되돌릴 수 있는 작은 선택은 표시한 가정으로 진행할 수 있지만, 핵심 성공 기준이나 데이터 의미를 조용히 가정하지 않는다. 합의된 범위에서 단계가 바뀐다는 이유만으로 다시 승인을 요구하지 않는다.

업무 결과가 달라지는 미확정 규칙은 추천안을 냈다는 이유만으로 기본 동작으로 구현하지 않는다. 영향받는 부분은 답변 대기로 두고 독립 작업을 계속한다. 별도로 허용된 가정 실험은 확정 구현과 분리하고 실험/미확정 상태로 기록한다. 실험 결과가 좋아도 답변·승인을 받은 것으로 바꾸지 않는다.

## 담당자 답변을 구현·검증으로 연결하기

질문 기록·사용자 알림·답변 보호·반영 상태는 [공통 QNA 절차](../../AGENTS.md#q--a--반영여부-사용법)를 따른다. 이 스킬에서는 업무 의미·운영 조건·우선순위를 구체화한다. 담당자는 알고리즘이나 정답을 대신 고르는 사람이 아니며, 다른 단계에서도 같은 Q ID와 답변을 재사용한다.

- 안내와 데이터에서 이미 확인한 사실을 먼저 분리한다. 질문은 실제 관찰·출처, 가능한 해석, 결과에 미치는 영향, 확인할 기준으로 구성한다. 관찰하지 않은 데이터 차이를 만들어 질문하지 않는다.
- **반드시 지킬 조건 / 가능하면 개선할 목표 / 데이터의 업무상 의미**를 구별한다. 목표끼리 충돌하면 우선순위·허용 범위·예외를 묻고, 임의 가중치를 합의된 업무 기준으로 사용하지 않는다. 이미 명시된 조건을 다시 확인받는 데 시간을 쓰지 않는다.
- 질문 초안에는 관찰·출처와 가능한 해석에 따른 결과 차이를 덧붙여, 가장 큰 재작업을 막는 기준부터 확인하도록 돕는다.
- 답변을 받으면 출처·적용 범위·예외를 기록하고, 실행 가능한 규칙과 작은 예시의 기대 결과로 바꾼다. 답변이 모호하거나 공식 지시와 충돌하면 해당 부분만 재질문한다. 답변을 받았다는 사실과 요구가 충분히 확정됐다는 판단을 구별한다.
- `질문 Q → 요구 R → 해법 결정 D → 구현 작업 → 검증 근거 E`를 기존 기록에 연결한다. 아직 구현·실행하지 않았다면 연결할 계획과 미검증 상태만 남기고, 완료 범위는 공통 QNA 기준으로 구별한다.
- 답변이 기존 기준을 바꾸면 영향받는 결정·계약·코드·테스트·생성 결과를 식별하고 해당 증거를 오래됨으로 표시한다. 허용된 수행 범위에서 수정·재검증하거나 필요한 다음 행동을 알리며, 질문 정리 요청만으로 개발을 시작하지 않는다.

기준이 정리된 해법 선택은 [fde-design](../fde-design/SKILL.md), 실제 결과의 독립 검증은 [fde-verify](../fde-verify/SKILL.md)로 이어간다. 모든 스킬을 한 번에 읽거나 전체 작업을 멈추는 승인 단계로 만들지 않는다.

## 남길 것

- MISSION 또는 과제 지정 문서: 문제 한 문단, R ID별 요구·출처·성공 기준·확인 방법, 관련 Q ID, 미확인 가정과 선택 범위.
- QNA 또는 기존 지정 Q&A 문서: Q ID별 질문·실제 답변·반영여부. Q와 A 본문을 MISSION에 중복 보관하지 않는다.
- DECISIONS: 중요한 범위·기준 선택이 실제로 생겼을 때만 이유와 결정 주체를 기록한다.
- STATE: 현재 주된 단계, 가장 큰 위험, 다음 행동을 짧게 갱신한다.

기존 기록을 우선한다. 새 기록이 필요하면 허용된 과제 작업공간에 사본을 만들고 위치를 명시한다. 배포 키트의 빈 양식이나 원본 문제 지시를 덮어쓰지 않는다.

첫 실행 흐름과 검증 기준이 충분하면 데이터 확인·설계·구현 중 필요한 작업으로 이어간다. 질문 목록 작성만으로 요구 확인 완료를 선언하지 않는다. 외부 전송·별도 AI·화면 자동 조작을 수행하지 않는다.
