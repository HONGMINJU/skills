# 검증 근거와 현업 시나리오

빈 양식이다. 실제 실행 또는 실제 사용자 관찰만 증거로 기록한다.

## 검증 목록

| 증거 ID | 관련 요구·작업 | 검사 종류·목적 | 실행 대상 버전·파일 범위 | 상태 | 상세 기록·로그 위치 |
| --- | --- | --- | --- | --- | --- |

검사 종류는 코드 리뷰·단위·통합·독립 검산·수동 UI·현업 시나리오 등을 구별한다. 상태는 통과·실패·미실행·오래됨을 사용한다. 검사 0건·전부 skip·환경 오류를 기능 통과로 기록하지 않는다.

## 실행 기록 양식 — 필요한 항목만 반복

- 증거 ID / 실행 시각 / 실행자:
- 연결된 요구·기준의 위치:
- 명령 또는 수동 조작 순서와 작업 폴더:
- 입력·데이터 기준 버전:
- 기대값과 근거: 실제 구현의 출력만으로 기대값을 만들지 않음
- 실제 결과 / 종료 코드 / 실행·skip 건수:
- 로그·결과 파일 위치:
- 판정과 확인하지 못한 범위:
- 코드 변경 후 유효성: 유효 / 오래됨 / 영향 미확인

Git이 없으면 파일 해시·변경 범위 등 가능한 기준점을 사용한다. 모든 작업에 전체 테스트를 반복할 필요는 없지만, 변경 영향을 받은 검사는 다시 확인한다.

## 실패와 재검사

| 실패 증거 ID | 원인·현재 가설 | 수정 파일·작업 ID | 동일 실패 사례의 재검사 ID | 남은 문제 |
| --- | --- | --- | --- | --- |

원래 실패 증거를 지우거나 기대값을 낮춰 통과시키지 않는다. 기대값 자체가 잘못됐다면 근거와 결정 변경을 남긴다.

## 현업 사용 시나리오

| 시나리오 ID | 사용자·업무 | 입력·수행 절차 | 기대 판단·행동 | 실제 관찰·관찰자 | 피드백·남은 차이 | 증거 ID |
| --- | --- | --- | --- | --- | --- | --- |

HTTP 응답과 화면 동작, 업무 적합성을 구분한다. 사용자의 실제 확인 전에는 확인 대기로 남긴다. 업무 담당자에게 피드백을 받지 않았다면 승인받았다고 쓰지 않는다.
