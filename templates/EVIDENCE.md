# 검증 근거와 현업 시나리오

빈 양식이다. 실제 실행 또는 실제 사용자 관찰만 증거로 기록한다.

## 검증 목록

| 증거 ID | 관련 요구·작업 | 검사 종류·목적 | 실행 대상 버전·파일 범위 | 상태 | 상세 기록·로그 위치 |
| --- | --- | --- | --- | --- | --- |

검사 종류는 코드 리뷰·단위·통합·독립 검산·수동 UI·현업 시나리오 등을 구별한다. 상태는 통과·실패·미실행·오래됨을 사용한다. 검사 0건·전부 skip·환경 오류를 기능 통과로 기록하지 않는다.

## 실행 기록 양식 — 필요한 항목만 반복

- 증거 ID / 실행 시각 / 실행자:
- 연결된 요구·기준의 위치:
- 명령 또는 수동 조작 순서와 작업 폴더:
- 입력·데이터 기준 버전:
- 기대값과 근거: 실제 구현의 출력만으로 기대값을 만들지 않음
- 실제 결과 / 종료 코드 / 실행·skip 건수:
- 로그·결과 파일 위치:
- 판정과 확인하지 못한 범위:
- 코드 변경 후 유효성: 유효 / 오래됨 / 영향 미확인

Git이 없으면 파일 해시·변경 범위 등 가능한 기준점을 사용한다. 모든 작업에 전체 테스트를 반복할 필요는 없지만, 변경 영향을 받은 검사는 다시 확인한다.

## 해법 판단 요약 — 방법·결과를 비교한 경우만

- 관련 결정 / 요구 / 담당자 답변:
- 독립 기대값·제약 검사기의 근거와 알려진 위반 탐지 결과:
- 실제 입력·조건·버전·실험 예산·재현 조건:
- 필수 제약 충족 범위와 위반:
- 유효한 기준안 대비 목적값·구성 지표·실행 시간·실패:
- 데이터·규칙 변경 후 재검증 범위와 오래된 증거:
- 최적성·불가능성 증명 여부와 적용 범위:
- 판단 / 미검증 / 재검토할 조건:

기준안과 같거나 더 좋다는 사실만으로 정답·최적성을 선언하지 않는다. 비교하지 않은 항목과 해를 찾지 못한 상태를 구별해 기록한다. 자세한 실행 근거는 위 증거 ID에 연결하고 숫자를 새로 만들어내지 않는다.

## 실패와 재검사

| 실패 증거 ID | 원인·현재 가설 | 수정 파일·작업 ID | 동일 실패 사례의 재검사 ID | 남은 문제 |
| --- | --- | --- | --- | --- |

원래 실패 증거를 지우거나 기대값을 낮춰 통과시키지 않는다. 기대값 자체가 잘못됐다면 근거와 결정 변경을 남긴다.

## 현업 사용 시나리오

화면이 있으면 이 표를 화면 테스트 확인표로도 사용한다. 접속 위치는 실제 포트·경로, 입력에는 초기 상태·준비 조건도 적는다. 화면이 없는 과제는 해당 결과물의 사용 절차로 작성하며 별도 UI 문서를 만들지 않는다.

| 시나리오·요구 ID | 사용자·업무 / 접속 위치 | 입력·조작 순서 | 기대 결과·판단 / 근거 | 자동 검사 증거 / 남은 직접 확인 | 실제 관찰·관찰자·상태 | 차이·재검사 증거 ID |
| --- | --- | --- | --- | --- | --- | --- |

기대 결과에는 요구·Q ID 또는 독립 계산 근거를 연결한다. 자동 검사 상세는 기존 증거 ID로 참조하고, 직접 확인 항목은 실제 관찰 전까지 `미실행(확인 대기)`로 둔다. HTTP 응답과 화면 동작, 업무 적합성을 구분하며 일부 자동 통과를 전체 완료로 표시하지 않는다. 수정 후 영향받는 관찰은 오래됨으로 남기고 재검사에 연결한다. 업무 담당자의 피드백이 없으면 승인받았다고 쓰지 않는다.
